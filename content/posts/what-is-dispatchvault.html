What is DispatchVault?

DispatchVault, usually shortened to Dispatch, is a software platform that governs AI-driven website work. When an AI coding agent such as Claude Code, Codex, or Gemini changes a website, Dispatch records who requested the change, which agent made it, what context it followed, who approved it, what it affected, and how to undo it.

Think of it as the control room above the tools that actually do the work. Webflow, WordPress, Vercel, and Netlify are execution platforms. GitHub is version control. Coding agents are the builders. Dispatch is the management layer that spans all of them, so a marketing team can operate an AI-powered website with the same confidence a traditional CMS used to provide.

Dispatch is deliberately agent-agnostic and host-agnostic. It does not build pages and it does not host your site. It connects to the repository and host you already use and adds oversight on top.

What problem does Dispatch solve?

AI coding agents have made website changes fast and cheap. That speed creates a new problem: nobody can see what changed, who asked for it, or whether it was reviewed. A traditional CMS bundled two jobs together, production and governance. AI has unbundled them. Agents now handle production. Dispatch handles governance.

Without a management layer, teams running AI-powered websites typically run into these issues:

  • No attribution. Commits land from agents and humans alike, and it is unclear which is which.
  • No approval trail. Changes go live without a preview or a named approver.
  • No shared context. Every agent session starts from scratch without the brand voice, messaging, or standards the team already agreed on.
  • Silent regressions. A title tag disappears, a canonical breaks, or structured data is dropped, and nobody notices until AI search and Google traffic fall.
  • Scary rollbacks. Fixing a bad change means finding the right commit and asking an engineer for help.

Dispatch addresses each of these with attribution badges, role-gated approvals, a versioned Company Brain, scheduled AEO crawls, and one-click restore. The DispatchVault team calls the underlying idea "governance is speed": fast, structured review replaces slow handoffs and hero-level human memory.

How does DispatchVault work?

A change in Dispatch follows a clear path from intent to deployment:

  1. Request. Someone on the team writes a plain-language change request, or Dispatch drafts one itself after a crawl finds a problem.
  2. Handoff. The request becomes a scoped handoff to an AI coding agent, carrying approved brand context and a risk tier.
  3. Branch and preview. The agent works on its own branch. The host generates a preview so reviewers can see the change before it goes live.
  4. Approval. Approvers review the preview. Roles prevent self-approval. High-risk requests require two distinct approvers.
  5. Deploy and record. The change deploys, and the activity feed records the request, the agent, the approver, and the result.
  6. Restore if needed. Any prior version can be restored in one click. Nothing is deleted, and the recovery is part of the audit record.

Every commit, pull request, and deployment streams into a live activity feed. Coding agents sign their commits with attribution trailers, and Dispatch reads those trailers to badge each change with the agent that made it.

What are the main features of DispatchVault?

Website governance

  • Risk tiers: low-risk requests can auto-approve by policy, standard-risk requests need an approver, and high-risk requests need two

The Dispatch Inbox

The Dispatch Inbox, launched in September 2026, is the single place where work waits for a decision. It holds four kinds of items: requests awaiting approval, crawl findings with a drafted fix ready, pages whose scores slipped since the last crawl, and work in progress. Approvers, operators, and owners each land on a view built for their role. Slack and email alerts include the draft and the recommended next step, so most decisions can be made from the notification itself.

AEO scoring

Dispatch crawls every governed page on a daily or weekly schedule and scores it from 0 to 100 for answer engine readiness. The score tracks eight checks: title tag, meta description, a single H1, canonical URL, structured data, Open Graph and social tags, indexability, and a clean HTTP 200 status. Structured data carries the heaviest weight. When a score drops significantly, Dispatch opens a finding and drafts the fix. This is the same discipline ZINC applies in our On-Brand AEO Sprint, and it turns AEO from a one-time project into an ongoing monitored system.

Company Brain

The Company Brain is a centralized, versioned, searchable library of approved prompts, brand voice guidelines, messaging, workflows, agents, and AI-generated assets. It is exposed to connected coding agents as an MCP server, so every agent works from the same approved context instead of guessing. This is the feature ZINC clients know from our AI Dispatch offering: one client-owned vault that ends prompt sprawl and keeps AI output on brand.

Multiplayer collaboration

  • Several people and several agents work at the same time without conflicts
  • Each request gets its own branch and its own preview
  • Agents follow the same approval rules as humans
  • Agencies can govern many client sites, each with its own repository, host, policies, and context, all reporting to one Inbox

How does DispatchVault compare to Webflow, Vercel, Netlify, and GitHub?

These tools are not competitors to Dispatch. They sit in a different layer.

  • Webflow and other CMS platforms combine production and governance in one hosted product. Dispatch keeps the governance benefits, such as visibility, permissions, and restore, without requiring the CMS as the production environment. Read the Webflow vs. AI-managed website comparison.
  • Vercel, Netlify, and Cloudflare host and deploy. Dispatch connects to them and adds requests, approvals, attribution, and scoring above the deploy.
  • GitHub stores code and history. It does not know who on the marketing team asked for a change, what brand context applied, or whether the page's AEO score moved. DispatchVault explains this gap in why GitHub alone is not enough to govern a marketing website.

The recommended 2026 stack is a Git-based site, a preview-first host, one or more coding agents, and a management layer that spans all three.

Can Dispatch approve changes automatically?

Only when a site's policy allows it for low-risk requests. Standard-risk requests require an approver, and high-risk requests require two distinct approvers. Every approval, including policy-driven ones, is recorded in the audit trail.

Am I locked into DispatchVault?

No. Your website code and history stay in your own repository and host. If you turn Dispatch off, the site keeps running exactly as it is, and all context, prompts, and workflows export as JSON and Markdown at any time.

Does moving to an AI-managed website hurt SEO?

No, provided the migration preserves URLs, redirects, titles, descriptions, canonical tags, sitemaps, and structured data. Dispatch migrations preserve all of these, and code-first sites often improve technical SEO because every signal is explicit in the codebase.

How is DispatchVault different from a prompt library?

A prompt library stores prompts. Dispatch manages prompts alongside agents, workflows, documentation, brand assets, governance policies, and website change approvals. It is closer to an AI operating system for the organization than a single library.
